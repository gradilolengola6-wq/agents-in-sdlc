まず、小さな機能をプロジェクトに追加しました。しかし、大きな変更には、より確実なプロセスが必要です。GitHub Copilot CLI は、組織で使われている既存の開発フローに沿って、適切な方法で必要な機能を作成できるように設計されています。このレッスンから、エージェント主導の一般的な開発プロセスに沿って作業します。issue から新機能を作成し、コードが正しいこと、期待どおりに機能することを確かめたうえで、プロジェクトにマージします。

> [!NOTE]
> 機能の作成を続ける間、同じ会話とブランチを使います。通常は作業対象のファイルの種類ごとに異なるブランチや PR を使いますが、ここでは主な概念に集中するため、一部を省略します。

このレッスンでは、次の内容を学びます。

- GitHub issue から新しい Copilot の会話を開始します。
- Plan モードで要件を定義します。
- Autopilot モードで新機能を実装します。
- コードをレビューします。
- ポートフォワードしたブラウザーで機能を手動で検証します。

機能の作成を続けながら、リポジトリの指示を更新し、既存の `quality-checks` スキルをカスタマイズし、MCP による検証を追加して QA エージェントを作成し、機能の PR を開きます。

## シナリオ

Tailspin Toys のカタログが増え、訪問者がカテゴリや発行元でゲームを絞り込めるようにする必要があります。バックログの issue には機能が説明されていますが、カテゴリを組み合わせる方法など、コーディング前に合意が必要な詳細があります。Plan モードで判断を確定し、Autopilot には範囲を明確にした実装を任せます。

## 背景

AI コーディングエージェントを開発フローに導入しても、基本は変わりません。むしろ、より重要になります。多くの開発者は、次のような流れで作業しています。

1. 実装する内容が記述された issue から作業を開始します。
2. 実装計画を作成します。
3. コードを作成してレビューします。
4. テストを実行してコードを検証します。
5. 新しい機能を手動で検証します。
6. プルリクエスト (PR) を作成します。
7. コードレビューと継続的インテグレーションが成功したら、コードをマージします。

> [!NOTE]
> チームや組織によって詳細は異なりますが、多くの場合は上記の流れを調整したものになります。

この標準的な方法を守ることで、AI が生成したコードが要件を満たし、手作業で作成したコードと同じレビューのプロセスを通るようにできます。

## 会話モード

**会話モード**は、エージェントの自律性の度合いを決めます。<kbd>Shift</kbd>+<kbd>Tab</kbd> を押すと、モードを切り替えられます。

- **Interactive**: エージェントと一緒に作業します。エージェントは変更を提案し、次に進む前にユーザーの入力を待ちます。
- **Plan**: エージェントが先に計画を作成します。プロジェクトファイルの編集はできません。
- **Autopilot**: エージェントは自律的に作業します。コードを作成し、テストを実行し、タスクの完了まで反復します。

最初に Plan モードで計画を確認し、次に Autopilot で実装します。

## issue から開始する

フィルタリング機能の作業を始める前に、Codespace に戻ってリポジトリとターミナルの準備をします。

1. Codespace に戻ります。停止している場合は、再起動してから続けます。
2. 星評価の PR がマージ済みであることを確認します。
3. ターミナルが開いていない場合は、<kbd>Control</kbd>+<kbd>\`</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>\`</kbd> (Windows/Linux) を押します。
4. `main` を更新し、フィルタリング作業用のブランチを作成します。

   ```bash
   git checkout main
   git pull --ff-only
   git checkout -b game-filters-cli
   ```

5. Copilot CLI を起動します。

   ```bash
   copilot --yolo
   ```

6. <kbd>Tab</kbd> を 2 回押して **Issues** タブを開きます。
7. <kbd>A</kbd> を押してすべての issue を表示します。
8. 矢印キーを使って、**Allow users to filter games by category and publisher** というタイトルの issue を選択します。
9. <kbd>C</kbd> を押して issue をプロンプトに追加し、**Session** タブに戻ります。

プロンプトが `#7` (または同様の番号) で始まっていることを確認します。`#` を使うと、GitHub 上の issue やプルリクエスト (PR) をコンテキストに含められます。

## フィルタリング機能を計画する

計画を立てると、Copilot に作業を依頼する前に、機能の実装方法やタスクの進め方を決められます。複雑な作業では、時間をかけて計画するのが効果的です。Plan モードに切り替えて、Copilot に計画を作成してもらいましょう。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Plan モードに切り替えます。プロンプトの下にあるモード表示が **Plan** になっていることを確認します。
2. 前の手順で追加した issue の参照の後に、次のプロンプトを入力します。

   ```plaintext
   Create a plan for implementing this feature.
   ```

Copilot が計画を作成します。まずプロジェクトを調べてから、適切な方法を判断します。

3. フィルタリングの動作について Copilot から質問されたら、自分の希望に基づいて回答します。正解は一つではありません。
4. 計画が完成したら、<kbd>Control</kbd>+<kbd>E</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>E</kbd> (Windows/Linux) を押して計画を展開します。
5. 計画を上下にスクロールして確認します。
6. 判断と異なる内容があれば、Copilot に計画の修正を依頼します。

## Autopilot を承認する

計画を作成してレビューしたので、次は実装します。Autopilot を使って Copilot に作業を任せます。

Autopilot を使うと、Copilot はタスクが完了したと判断するまで問題に取り組みます。

1. **Accept plan and build on autopilot (recommended)**、またはインストールしたバージョンに表示される同様の項目を選択します。
2. プロンプトの下にあるモード表示が **Autopilot** になっていることを確認します。
3. Copilot が計画に沿って作業を進め、コードを生成してテストを実行する様子を確認します。

> [!NOTE]
> 承認すると、実装がすぐに始まる場合があります。事前に計画を確認してください。Copilot から依存関係の不足やポートの競合が報告された場合は、チェック完了と判断する前にセットアップの問題を解決してください。

## 実装をレビューして検証する

他のコードと同様に、生成されたコードもマージ前にレビューする必要があります。コードを確認し、サイトを実行して問題がないか確認しましょう。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Interactive モードに切り替えます。モード表示に **Plan** または **Autopilot** と表示されていないことを確認します。
2. `/diff` を入力し、フィルタリングの実装とテストを確認します。
3. issue および計画で決めた内容と実装を比較します。
4. コードをレビューしたら <kbd>Esc</kbd> を押して差分ビューを閉じます。
5. プロジェクトのチェック結果を確認し、失敗があれば Copilot に解決を依頼します。

## 新機能を試す

コードに問題がないことを確認したので、実際に動くかテストしましょう。前と同じようにアプリを起動し、Codespaces が転送したポートを使ってサイトを開きます。

1. Copilot にアプリの起動を依頼します。

   ```plaintext
   Start the app so I can try the filtering feature in my browser. Tell me the URL and leave the server running.
   ```

2. Codespaces でポート `4321` が利用可能になったら、**Open in Browser** を選択します。
3. 計画で決めたカテゴリフィルター、発行元フィルター、組み合わせを試します。
4. リセット時と検索結果がない場合の動作が、issue と決定事項に合っていることを確認します。
5. Codespace に戻り、起動した開発サーバーを停止するよう Copilot に依頼します。

## まとめと次のステップ

会話モードを使い分けて、機能を作成し、レビューしました。このレッスンでは、次のことを行いました。

- GitHub issue から新しい Copilot の会話を開始しました。
- Plan モードで要件を定義しました。
- Autopilot モードで新機能を実装しました。
- コードをレビューしました。
- ポートフォワードしたブラウザーで機能を手動で検証しました。
