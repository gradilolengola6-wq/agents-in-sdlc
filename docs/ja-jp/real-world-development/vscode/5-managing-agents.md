GitHub Copilot をエージェントモードにすると、コードベースを調べ、変更を提案してファイルを編集し、コマンドを実行します。VS Code の Copilot Chat では、ユーザーのマシンでリアルタイムに実行される各ツール呼び出しやファイル編集を確認できます。差分をインラインでレビューし、個々の変更を採用または取り消したり、エディターを離れずに追加のプロンプトを送って会話を進めたりできます。

この演習では、次の内容を学びます。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして採用します。
- セッション中にエージェントへ指示を追加し、ハイコントラストモードに加えてライトモードの切り替え機能も追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタムエージェントは、ハイコントラストモードを実装しています。作業中に、デザインチームから追加の依頼がありました。デフォルトのテーマが暗すぎると感じるユーザー向けに、ライトモードの切り替え機能も追加したいとのことです。新しい会話を最初から始める代わりに、既存のセッションに指示を出して作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューでは、エージェントが実行する各手順、調査したファイル、実行したコマンド、提案した編集を確認できます。各ファイルの編集は差分と **Keep** / **Undo** ボタンとともに、チャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントが作業している間、チャットをスクロールしてツール呼び出しを確認します。ファイルの読み込みや編集、実行を求めるターミナルコマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がチャット内に表示されます。
    - 変更を採用するには **Keep** を選択します。
    - 変更を取り消し、エージェントにやり直してもらうには **Undo** を選択します。
4. チャット上部の **Files changed** の表示を開くと、セッション中にエージェントが変更したすべてのファイルを確認できます。

> [!NOTE]
> ターミナルコマンドの実行などで許可が必要な場合、エージェントは一時停止して **Allow** を求めます。内容を確認し、許可してもよいコマンドだけを承認してください。

5. エージェントがハイコントラストモードの実装を終えるまで待ちます。最後に、行った変更をまとめたメッセージが表示されます。

## ライトモードを追加するようエージェントに指示する

ハイコントラストモードが実装されたので、同じ会話でライトモードの切り替え機能を追加します。同じチャットセッションを続けるため、エージェントは前の作業から得たコンテキストを保持しています。変更したコンポーネント、採用したスタイル、設定したローカルストレージの使い方などを引き継ぎます。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは前の変更を調べ、ライトモードを追加する提案をします。
3. ハイコントラストモードのときと同じように、新しい編集を確認して **Keep** または **Undo** を選択します。
4. エージェントの作業が希望と異なる場合は (たとえば、切り替え UI を意図しない方法でリファクタリングしようとした場合)、チャット入力欄の隣にある **Stop** ボタンで作業を止め、補足プロンプトを送信します。

> [!TIP]
> セッションの途中で指示を追加すると、最初からやり直すよりも速く進められます。追加のプロンプトを使って、調整を依頼します (「CSS を簡略化し、セレクターの重複ではなく CSS 変数を使ってください」)、方向を修正します (「3 つ目の切り替えボタンを追加せず、ライトモードを既存の設定パネルに組み込んでください」)、範囲を広げます (「両方の切り替えにキーボードショートカットも追加してください」)。

## 作業内容をレビューする

コミットする前に、エージェントが変更したファイルをまとめて確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されています。
3. 変更したファイルをいくつか開き、差分を確認します。アクセシビリティ用カスタムエージェントが示した ARIA 属性、キーボード操作、セマンティック HTML、ローカルストレージによる保存などのパターンが反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードを使って、進行中のセッションを監視し、指示を追加しました。ファイル編集ごとに内容をレビューして採用または取り消し、コンテキストを保ったまま追加のプロンプトを送信しました。

このレッスンでは、次の内容を学びました。

- エージェントの作業をリアルタイムで監視する方法
- 個々のファイル編集を採用または取り消す方法
- セッション中に追加のプロンプトを送って指示する方法
